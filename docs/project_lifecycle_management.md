# 项目参数作用域与项目管理设计

## 参数的唯一数据流

科学参数只有三层，不存在可变的“本机全局参数”：

```text
resources/config/project.yaml（打包默认值，只读）
                ↓ 新建项目
<project>/config/project.yaml（项目持久化）
                ↓ 深拷贝
工具页会话参数（临时覆盖）
```

- `load_factory_project_settings()` 直接读取打包资源，不经过用户目录或仓库根目录的 `config/` 覆盖。
- `ProjectSettings` 的 dataclass 默认值只负责旧配置缺字段时兜底。
- 项目配置的读写必须带明确项目路径；无活动项目时 Manager 不能 `get/set/save`。
- 工具页只接收项目快照。控件修改保留在当前会话，关闭软件、切换项目或切换数据上下文后重建。
- 根目录 `config/*.yaml` 只作为旧版本显式迁移或指定路径导出的兼容文件，不参与正常初始化。

## 项目管理页

项目管理页固定为三个页签：

1. **项目与数据**：项目身份、项目根目录、新建/打开/关闭、项目内数据登记及校验状态。
2. **定标与卡峰**：质量定标、定标点状态和当前项目卡峰范围。
3. **项目分析参数**：通用分析、温度扫描、PIE、PICS、摩尔分数。

“定标与卡峰”表示项目中由实验数据建立、被多项分析共同引用的基准事实，
不承担一般算法选项。寻峰与积分页包含光强来源和自动寻峰；温扫与 PIE 的积分
策略分别归各自模块，各工具页仍可在当前会话中临时覆盖。

模块专属参数保留在对应页签：

- PIE 物种匹配使用的元素范围归 PIE。
- 摩尔分数质量响应预设和指数归摩尔分数。
- PICS 使用自己的质量响应指数，不隐式读取摩尔分数参数。

页面共享一份内存草稿。页签切换和控件失焦只更新草稿，不写文件、不更新工具页。离开项目页、关闭项目、打开另一项目或新建项目时，未保存草稿统一提示“保存并应用 / 放弃 / 取消”。

三个动作严格分离：

- **保存项目**：创建标准目录并保存项目身份和完整工厂初始配置，不复制数据。
- **导入项目数据**：唯一的外部数据复制入口，使用后台 Worker，并写入 `raw_data/_sources.yaml`。
- **保存并应用项目参数**：一次验证定标、卡峰和分析参数，原子替换 `project.yaml`，成功后广播新的项目快照。

PIE 能段取消登记不会自动删除已经复制到项目内的文件。卡峰导入、自动生成和质谱工作台“保存卡峰范围到项目”是明确的即时基准操作，历史快照继续由后台维护。

## 字段所有权

- 项目身份：`project_name`、`system`、`description`、`output_dir`。
- 数据源：原始谱、温扫、PIE、Kr 等路径及 PIE 能段列表。
- 定标与卡峰：定标 A/B/C、定标点、当前卡峰文件和卡峰快照 ID。
- 通用分析参数：光强来源和自动寻峰。
- 模块分析参数：`temp_*`、`pie_*`、`pics_*`、`mf_*`；PIE 同时拥有
  `selected_elements`，PICS 和摩尔分数分别拥有自己的质量响应指数。
- 产物：曲线数据库和各模块结果路径。
- 内部派生：`temp_peak_source`、`pie_multi_folder_mode`、`temp_prefer_gaussian`、`pie_prefer_gaussian`。
- 旧版兼容：`mass_discrimination` 只允许旧项目读取，新的项目文件不再写入；
  旧项目缺少 `pics_mass_disc_exponent` 时可由兼容层从
  `mf_mass_disc_exponent` 初始化一次，保存后两者独立。

派生字段由项目保存服务从主字段和当前基准计算，界面不能用隐藏控件覆盖。
`PROJECT_FIELD_OWNERS` 对上述分类进行代码级约束，新增字段必须先声明唯一所有权。

## 工具页显式回写

工具页的“更新项目参数”通过模块白名单合并。服务会先重新加载已提交项目，再合并补丁，防止一个工具用旧快照覆盖其他模块：

- 质谱：定标、定标点、寻峰参数；卡峰范围使用独立保存动作。
- 温扫：`temp_*`、Kr 配置与膨胀系数。
- PIE：`pie_*`、同位素 QC 参数和物种匹配元素范围。
- PICS：`pics_*`，包括 PICS 自己的质量响应指数。
- 摩尔分数：`mf_*`。

显式保存分析结果、导入数据和保存卡峰范围可以更新对应产物或基准字段，不属于隐式科学参数回写。Kr 膨胀系数计算只在温度扫描页出现；计算结果先进入温扫会话，点击“更新项目参数”后才持久化。

## 持久化与兼容

项目 YAML 使用同目录临时文件写入、刷新并原子替换。失败时原文件保持不变，界面草稿继续保留。旧版嵌套/平铺 YAML、相对路径重定位和旧卡峰迁移继续由加载兼容层处理；`migrate_from_legacy_configs()` 只保留为显式兼容工具。

## 科学可靠性升级说明

- 工厂配置保持中性：默认不启用温扫 Kr 质量响应校正，不预置 Kr 卡峰文件、膨胀系数或摩尔分数 Kr 数据，寻峰算法默认使用 `ensemble`。升级后如需质量响应校正，必须在项目或本次临时分析中显式配置并核验。
- PIE 原始谱缺少或包含无效的 IO、采集时间时会停止分析并报告错误，不再以 `0` 或 `1` 静默替代。
- PIE 跨能段合并在共享峰证据不足时会停止并说明拒绝原因，不再静默使用 `1.0` 缩放因子。
- 二次定标要求至少三个不同定标点，并且使用的 TOF→m/z 分支必须在有效范围内单调递增；旧版本可接受的歧义定标可能会被拒绝。
- `ProjectSettingsManager` 在没有活动项目时不允许项目级读写或保存。临时数据使用独立的工厂快照和会话参数，不需要新建项目。
